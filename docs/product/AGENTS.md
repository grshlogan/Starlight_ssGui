# 产品章程 — Starlight_ssGui

状态:`Proposed`(所有者逐项确认后提升并记录日期)/ Owner: 项目所有者。只记录已确认方向;未确认项标 `hypothesis`。

## 使命

为 Topaz Video 的星光(SLP 2.5 / 2.6)本地渲染提供**开源、中文、可脚本化**的配套工具:
做两件事——**参数调优注入**与**渲染日志监控**。面向需要长时间跑 SLP、希望压榨硬件且看清进度与参数的桌面用户。

来源项目/旧实现(learn 快照与闭源分析)只是需求证据与失败案例来源,其历史决策不自动成为本项目需求。

## 交付顺序

1. **Stage 1 技术验证**:注入最小闭环 + 真实渲染日志采样锁定解析格式。验收:在真实 Topaz(Windows,当前 1.7.x)上注入可生效且可自证(审计 JSONL 对照),日志可稳定解析出阶段/分块/进度。
2. **MVP**:完整参数集注入(含预设)+ 日志监控(阶段/进度/ETA/历史)。验收:一次真实导出全程参数与进度可视化,无漏报/错报。
3. **后续(未排期)**:cuDNN 运行时管理、自动调优(autotune)等,另行立项。

顺序即验收顺序:后一阶段不能替代前一阶段的证据。

## 范围

- SLP 参数注入:完整参数集(环境变量→目标模块属性/包装器),**进程内**生效,不改 Topaz 安装文件。
- 目标模块动态发现与契约校验(适配 Topaz 版本升级)。
- 审计自证:hook 每次变更写 JSONL,供"设置 vs 生效"对照。
- 渲染日志监控:主日志(tzlog)双方言解析、阶段/分块/fps/ETA、完成历史。
- 参数预设与持久化(按显存自动预设,可手工微调)。

## 保护与合规策略

- 默认**不写 Topaz 安装目录**;任何显式写操作(如可选的 cuDNN 替换)必须可回滚、逐项授权、且先备份。
- `learn/` 快照与闭源分析产物**只读**;对两个闭源工具只学习其公开机制,不搬运代码、不重新发布反编译产物,引用注明来源。
- 不包含破解、激活、许可规避相关功能;不接触模型权重本体。

## 非目标

- 视频转码链:分段、超分+插帧流水线、音轨合并(参考项目 TopazStarlightUI 已有该类职责)。
- 安装器/自动更新/云功能/账号操作。
- 对 Topaz 的破解或逆向其模型权重、绕过许可。

## 基础阶段限制

任务包明确授权前,不得进行:产品代码、协议或真实账号操作、打包/发布、可执行原型。

## 领域词汇

| 术语 | 定义与边界 |
| --- | --- |
| SLP / 星光 | Topaz 扩散式视频修复模型 Starlight Precise(2.5/2.6),经 neuroserver 本地运行 |
| 调参注入(hook) | 把参数写进 neuroserver 子进程内模型模块的机制;进程级、可回退 |
| sitecustomize | CPython 启动自动导入的定制模块,作为注入载荷入口 |
| 目标模块 | neuroserver 内 `models.slp2*.<hash>` 编译模块;注入的实际对象 |
| 审计 JSONL | hook 变更记录(时间/pid/事件/变更明细),用于自证 |
| 阶段(Phase) | 渲染三段:VAE Encode → DiT Upscale → VAE Decode |
| 分块(chunk) | 时间窗口处理单元;fps=分块帧数/分块耗时 |
| warm-up 分块 | 首个完整分块;ETA 统计需排除 |
| 主日志(tzlog) | Topaz 写入的 `*-Main.tzlog`;日志监控主数据源 |
| 方言 | 不同 Topaz 版本的日志格式差异(1.7.0 / 1.7.1+) |
| ETA | 基于稳定均值的剩余时间估计 |

## 产品不变量

1. 注入失败必须**回退原生运行**——不得阻塞渲染、不得降低产出正确性。
2. 默认不修改 Topaz 安装文件;一切写操作需授权、可回滚、先备份。
3. 监控数据只从真实日志/进程证据推导;无法解析时显式显示"未知",不得伪造进度。
4. 一切技术结论可追溯(快照 / 分析报告 / 实测记录),不凭记忆写入文档。
