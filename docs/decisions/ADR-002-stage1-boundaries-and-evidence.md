# ADR-002：Stage 1 的闭环顺序、模块 seam 与证据门

Status: accepted（所有者已确认方向；实测证据仍待 Stage 1 关闭）

Stage 1 先完成注入、审计和原生回退的最小闭环，再完成日志监控；交付顺序选择注入优先，是为了先验证产品最核心且失败影响最大的运行路径。注入首选 `PYTHONPATH + sitecustomize`，默认不写入 Topaz 安装目录，注入不能安全完成时必须回退原生启动。日志以 Topaz 主日志 `tzlog` 为首批主源，`neuroserver stdout` 作为补充源，并为版本差异保留方言解析空间。

GUI 与 backend 之间采用少量控制命令、状态快照、结构化事件和结构化错误的 seam。原始日志、进程生命周期、文件系统和注入细节归 backend；GUI 只消费结构化结果。Stage 1 同时使用本地日志夹具进行快速回归，并使用 Windows x64 + 真实 Topaz 证据关闭阶段门；缺少真实环境时相关验收保持 `BLOCKED`。

## 考虑过的选项

- 并行完成注入和日志最小闭环：暂不采用，因为注入失败会影响启动与回退，是更早的风险门。
- `.pth` 引导器：保留为注入 spike 的失败候选；它可能要求写入 Topaz 安装目录，与“不默认写安装文件”不变量冲突。
- GUI 直接读日志/JSON 文件：暂不采用，因为会泄漏 backend 的原始日志、进程和文件系统职责，形成浅 seam。
- 只用本地夹具验收：暂不采用，因为夹具无法证明真实 Topaz 中注入生效和原生回退。

## 后果与验证门

Stage 1 的任务拆分必须先覆盖 pocketjs 宿主能力 spike，再覆盖注入审计/回退和真实日志采样，最后冻结 GUI/backend 的最小接口。验证必须记录 Windows 环境、Topaz 版本、注入前后对照、回退结果、日志夹具哈希与解析输出；任一关键证据缺失都不能宣称 Stage 1 已关闭。pocketjs 是否直接满足进程、文件监听和定时读取能力仍是独立的 Stage 1 未决验证项。

采纳人：项目所有者（当前会话确认）。
