### 2.2 skv89(多模块版,含大量设计注记)

```python
# —— 命令行解析(容错前后缀) ——
'(?:^|\\s)--input-path\\s+(.+?)\\s+--output-path(?:\\s|$)'
'(?:^|\\s)--output-path\\s+(.+?)\\s+--start-frame-idx(?:\\s|$)'
'(?:^|\\s)--start-frame-idx\\s+(-?\\d+)'
'(?:^|\\s)--end-frame-idx\\s+(-?\\d+)'
'(?:^|\\s)-c:v\\s+([^\\s]+)'            # 编码器(h264_nvenc 等)
'(?:^|\\s)-profile:v\\s+(\\d+)'
'(?:^|\\s)-fps_mode\\s+\\S+\\s+(.+?)\\s*$'

# —— 运行器生命周期 ——
'\\bRunner process started\\s+(\\d+)\\b'          # 进程启动(真正的处理边界候选)
'\\bFF Process Output:\\s*(\\d+)\\b'
'\\boutput_uri:\\s*(.+?)\\s*$'
'\\bprocess exited:\\s*(\\d+)\\s+(-?\\d+)(?:\\s+(-?\\d+))?'   # 退出码/时长
'^(\\d{4}-\\d{2}-\\d{2} \\d{2}-\\d{2}-\\d{2}\\.\\d{3})'      # 行时间戳
# 标记文本:'EventTracker: Video Export Started' | 'Runner process started' | 'Phase 1: VAE Encode'
```

### 2.3 监控设计注记(skv89 docstring,价值极高)

- `Video Export Started` 是**队列/请求事件,不是可靠的“开始处理”边界**——可能在上一个视频还在跑时就为下一个视频打出来；应以**带时间戳的 Runner process started** 为准。
- 第一个 `Phase 1: VAE Encode` 出现在**模型加载 + 输入估计之后**；该标记与启动标记之间的间隔 = 预处理时间,**与分块 FPS 计时分开统计**。
- 分块 fps = 该块帧数 / 该块全部耗时；**稳定均值 = 排除首个 warm-up 大块和末尾短片**后的均值;全程均值另算。
- Topaz 在外部取消/关窗时**不一定写结束行** → 需要用进程快照(`process_snapshot`)对账,不能只信日志。

## 3. Hook 安装机制(比我方文档原方案更稳)

| | naxci1 | skv89 |
|---|---|---|
| 注入方式 | **写 `.pth` 到 neuroserver 的 site-packages** → 启动时 import 引导器 | **PYTHONPATH 指向 hook 目录** → sitecustomize 自动导入 |
| 防篡改 | 引导器校验:`文件名必须是 sitecustomize.py`、大小 ≤2MB、**SHA-256 匹配**(`SLP_LITE_HOOK_FILE` + `SLP_LITE_HOOK_SHA256`),然后 `exec(compile(...))`;`sys._slp_lite_hook_loaded` 防重复 | 目标模块身份校验:`TOPAZ_SLP_TARGET_MODULE_NAME/PATH/SIZE/SHA256`;连 Topaz 主程序也校验(`TOPAZ_SLP_TOPAZ_EXE_PATH/SHA256/SIZE`) |
| 设置传递 | `TOPAZ_SLP_SETTINGS_FILE`(JSON:`schema_version/revision_id/environment_overrides`) | 同左 |
| 审计 | `TOPAZ_SLP_OVERRIDE_AUDIT_FILE`(JSONL) | 同左 |
| 其它 | `TOPAZ_SLP_BOOTSTRAP_FILE/SHA256`(新版引导器)、`TOPAZ_SLP_LAUNCH_ID`、`TOPAZ_SLP_NEUROSERVER_DIR` | `TOPAZ_SLP_EXPLICIT_ENV_KEYS`、`TOPAZ_SLP_FFPROBE_PATH` |

> 对 Rust 工具的建议:首版用 PYTHONPATH(simple),可选升级 `.pth`+SHA256(更抗干扰);
> 两者参数格式一致,**Rust 侧只负责写 JSON + 设环境变量**,Python hook 当数据文件发。

## 4. cuDNN 逻辑(双工具实证)

- **naxci1**:从 **PyPI files.pythonhosted.org 固定 URL** 下载(已提取到 4 条精确链接:cu12/cu13 × 9.24.0.43/9.24.1.1),用 pypi JSON API 校验;更新检查走 GitHub API;外网 IP 探测 `api.ipify.org`。
- **skv89**:`CuDNNController`——许可证确认 → 下载 → **SHA-256 全量校验** → 备份(`*.dll.bak`) → 替换;可"Restore Topaz 原生 cuDNN";AutoTune 用**子进程本地 cuDNN**(import hook 预载,**不动 Topaz 安装、不需要 UAC**)。
- 社区实测基准:cuDNN **9.24.0.43 (cu12) ≈ +32.8%**;9.24.1.1(cu13 栈)标注"fastest tested"。
